## 0. Méthode

1. **Lecture des sources** — `Shared/Catalogs/Loot.lua` (RARITY_COLOR, lignes 1270-1278), `Shared/Catalogs/Items.lua` (ITEM_DB, 26 objets), `Shared/Logic/Inventory.lua` (EQUIPMENT_SLOTS_ORDERED, lignes 86-93). Aucun identifiant inventé : tout est copié de ces fichiers.
2. **Mesure réelle des couleurs** — analyse PIL de chaque PNG `quality` (luminosité pour les gris, pixels saturés pour les teintes) pour choisir par hex, pas par intuition.
3. **Mesure réelle des icônes items** — analyse PIL : **toutes les icônes `items` sont en niveaux de gris pur (chroma max = 0 sur les 67 fichier)**. C'est un set monochrome dessiné pour être teinté au rendu (filtre CSS / shader). La couleur ne distingue donc pas les icônes : **seul le sens de la forme compte**.
4. **Validation** — chaque chemin référencé est testé par `fs.existsSync` (139 chemins testés, 0 mort). Sortie exacte en §7.

## 6. Observations techniques

- **Set monochrome :** les 67 icônes items ont un chroma de 0 (mesuré sur chacune). L'UI devra **teinter** (CSS `filter`/`drop-shadow` ou `<canvas>`/shader) pour donner du relief — sinon tout sera gris. Les `quality` (slot + glow) sont, eux, **en couleurs** (mesurés).
- **`silver/gold/flat/brown`** = le même jeu de 55 icônes en 4 teintes : si l'UI veut des icônes colorées sans tint, ces dossiers sont prêts.
- Aucun fichier `.lua` ni PNG existant n'a été modifié. Seuls `icones.json` et ce rapport ont été créés.
